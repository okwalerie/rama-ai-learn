# Claims and leases plan

One ordered execution-event depot and one microbatch topology remain the authority. Extend the per-execution PState with a bounded `:state` value (DAG, clock, node attempts/leases/results) and a subindexed `:claims` map keyed by claim-id. An unknown-execution claim writes its denial to `:claims` without creating `:state`; later submission updates only `:state`. A replay first checks the claim-id, irrespective of its new body or current clock. For fresh claims, check existence, node, success, dependencies, active lease in that order; grant increments only that node's attempt count and sets expiry C+10. Claim decisions are immutable and never garbage-collected.

The subindex is necessary: claims per execution are unbounded, whereas the DAG and node state are capped at 32. One-key point lookups for claim IDs avoid scanning history; a bounded state read determines fresh claims. Hash partitioning by execution-id means one task and constant seeks independent of total execution count or task count (N=1,16,128: a bounded state read plus a point claim lookup; replay only needs the point lookup). A separate claims PState would add per-task overhead; a flat execution record containing all claims would materialize unbounded history. Microbatch atomicity covers writing a grant and its decision together, including retries. No wall-clock scheduler is needed; expiry is evaluated on access using the explicit clock.

Self-check: unknown denial at C=0 then submission leaves denial intact; replay with a different worker cannot grant; at C=10 a lease expiring at 10 is invalid and a fresh claim gets token 2. A claim at C=9 is denied lease-held. The same depot/topology preserves advance→claim order.
